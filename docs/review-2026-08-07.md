## 1. Code quality (`clean-code-guard`)

| Severity | Finding | Location |
|----------|---------|----------|
| HIGH | Filter change does not reset `page`. On `?page=3`, applying a country/category/search keeps `page=3`; `page.tsx` clamps it, so users land on the *last* page of the new result set instead of page 1. | `src/app/[locale]/HomePageClient.tsx:33-43` |
| HIGH | Arabic search is shallow. `normalizeArabic` only strips diacritics; it does not unify alef variants (أ إ آ → ا), yaa/alef-maqsura, or ta-marbuta. Searching `احمد` will not match `أحمد`. Core-feature quality gap. | `src/lib/search.ts:1-5` |
| MED | `ScholarList` reads `t('noScholarsFound')` from namespace `'scholar'`, but that key was removed from `scholar.json` — it only resolves via `fallbackNS: 'common'`. Works today, fragile tomorrow. | `src/components/ScholarList.tsx:11,24` |
| MED | Language data is stored as raw display strings (`'Arabic'`), so the LanguageFilter shows English names even in the Arabic UI. No ISO codes, no localized labels. | `src/data/scholars/*.ts`, `src/components/filters/LanguageFilter.tsx` |
| MED | `SocialMediaLinks` is a large `switch` over magic icon strings (`'FaTwitter'`) hard-coded in the data — OCP smell, and couples data to a library's export names; renames silently fall back to `FaLink`. Prefer a `Record<platform, Icon>` map. | `src/components/SocialMediaLinks.tsx:16-32` |
| LOW | `onSearchChange` is recreated every render, so the debounce effect re-subscribes each render. Stabilize with `useCallback` or a ref-backed timer. | `src/app/[locale]/HomePageClient.tsx:63`, `src/components/filters/SearchInput.tsx:49-54` |
| LOW | Defensive `if (!scholar.name)` guards a case the `Scholar` type contract excludes. Data is hand-authored, so it is arguably justified — keep or drop deliberately. | `src/components/ScholarCard.tsx:21-26` |
| LOW | Global `* { border-color }` duplicates Tailwind v4 preflight; harmless but redundant. | `src/app/globals.css:102-106` |

**What is good:** command/query separation respected; functions are small and single-purpose; names reveal intent; no swallowed errors; no hardcoded "success" returns; `Button` variants are clean; pagination windowing is correct; the `useSyncExternalStore` (ThemeToggle) and render-time `setState` sync (SearchInput) are the *correct* React 19 idioms, not violations.

## 2. UX / accessibility (`impeccable`, static)

| Severity | Finding |
|----------|---------|
| HIGH | **Amber accent fails WCAG AA as text in light mode.** `--accent: oklch(0.72 0.14 68)` (≈ `#d99936`) on the near-white background is ≈ 3.0:1 contrast. It is used by `.text-eyebrow` (the 12 px hero label), which needs 4.5:1. Dark mode is fine (≈ 7:1). Fix: introduce a darker accent for text, or render the eyebrow in `foreground`. |
| MED | `--muted-foreground` (light) `oklch(0.50 0.02 250)` is ≈ 4.2:1 on the background — borderline fail for small body text (bios, labels). Darken slightly. |
| LOW | Pagination chevrons do not auto-flip in RTL (`rotate-180` is physical). Verify "previous" points the correct way in Arabic. |
| LOW | Inputs use `focus:` rather than `focus-visible:`, so the focus ring also appears on mouse click. Cosmetic. |

**What is good:** skip-link present; ARIA labels and `aria-current` on pagination, search, theme toggle, and language switcher; social links expose `sr-only` text; logical properties (`ps-/pe-/start-/end-`) used for RTL; `prefers-reduced-motion` honored; no impeccable design-law bans hit (no side-stripe borders, no gradient text, no decorative glassmorphism — the header `backdrop-blur` is purposeful).

## 3. Security / distribution (`ship-ready`)

**Good:**
- `X-Content-Type-Options`, `X-Frame-Options: DENY`, and `Referrer-Policy` are set (`next.config.ts:6-17`).
- No secrets in the repo; `metadataBase` is env-driven.
- sitemap, robots, manifest, and OpenGraph metadata all present.
- The middleware `x-locale` header is overwritten server-side (not spoofable from client input).

**Missing / should add:**
- No **Content-Security-Policy**, no **HSTS**, no **Permissions-Policy**. Add at least a `default-src 'self'` CSP that permits the inline theme script and Next internals.
- **No CI** (`.github/workflows` absent) — lint and build run only locally.
- **No production error monitoring** (only `console.error`).

## 5. Tests (`test-guard`, advisory — none exist)

There are no test files and no test script. Recommended minimal **Vitest** setup, targeting behavior (Rule 1) and mocking only at boundaries:

- **Extract `filterScholars(scholars, criteria)`** from `page.tsx` into a pure function — currently inline and untestable. Test: search (en/ar), country, language, category, and the empty/one/many boundaries.
- `src/lib/search.ts normalizeArabic` — boundary cases; extend coverage once alef-unification lands.
- `Pagination` `getPages()` — windowing edges (total ≤ 7, near first/last page).
- `src/lib/theme.tsx` resolved-theme logic.
