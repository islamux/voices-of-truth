## Important findings

- `src/components/filters/CountryFilter.tsx:1` — *AI-failure/E-10*: missing `'use client'` directive, while identical sibling `CategoryFilter.tsx:1` and `LanguageFilter.tsx:1` have it. It works today only because it is rendered inside client-bound `FilterBar.tsx`. [`import { useFilters } from '@/context/FilterContext';`] It would fail on server-component serialization if composed elsewhere. Fix: add `'use client';` as line 1.

- `src/app/[locale]/page.tsx:34-57` — *SRP / untestability*: filtering unconditionally, query-param validation (23-32), and pagination (55-57) are all inline in the page component and unreachable by tests. Prior review (08-07) recommended extracting `filterScholars`; never done. Fix: extract `filterScholars(scholars, criteria): Scholar[]` and `paginate(list, page, perPage)` into `src/lib/`, compose in the page.

- `src/app/[locale]/HomePageClient.tsx:37-53` + `src/components/Pagination.tsx:50-62` — *DRY (same knowledge)*: both `handleFilterChange` and `goToPage` hand-roll near-identical `URLSearchParams` mutation + `router.replace` under the same "delete when empty, keep `page` only when the change *is* page" rule. Fix: extract a shared `updateSearchParam(key, value)` (or `pushSearchParam`) helper in `src/lib/`, use in both.

- `src/components/ScholarCard.tsx:21-26` — *AI-failure/E-2, guard inside trust boundary*: `if (!scholar.name)` guards a field typed as required (`name: Record<string, string>`) fed by validated local data. [`if (!scholar.name) { ... return null; }`] Fix: remove the guard (or lift validation to the data boundary — `scholars.ts`).

- `src/components/ScholarList.tsx:56` — *AI-failure/E-2, dead guard*: `if (!scholar || !scholar.id || !scholar.name) return null;` re-checks values the `Scholar[]` contract already excludes and silently collapses grid cells. Fix: drop the guard; rely on the typed array.

- `src/types/index.ts:15,25` — *type safety / consistency*: `name: Record<string, string>` and `bio?: Record<string, string>` are looser than the sibling `Country { en; ar }`. Verified every name/bio uses exactly `en`/`ar`. Fix: introduce `interface LocalizedText { en: string; ar: string }` and use it for `name` and `bio` (schema-driven data → schema-driven types).

- `src/components/filters/LanguageFilter.tsx` — *Section B style*, *consistency*: whole-file formatting diverges from every sibling — `import React, {useMemo} from "react";` (double quotes, no space), `export default function LanguageFilter(){` (no brace space), `useMemo( ()=>`, stray blank lines, trailing `};`. Also `filterKey="language"` (line 25) mismatches the URL key used elsewhere (`lang`); siblings use their exact key. Fix: normalize to single quotes + spaced style; align `filterKey` to `'lang'`.

- `public/avatars/zain.jpg` — *dead asset*: tracked, present on disk, but referenced by no scholar (`zain_khairallah.jpg` is the one in use). Fix: `git rm public/avatars/zain.jpg`.

- `src/proxy.ts:4` — *DRY / single source of truth*: `const locales = ['en', 'ar']` duplicates `supportedLngs` in `src/lib/i18n.ts:6`. Fix: export `supportedLngs` from i18n and import it here.
